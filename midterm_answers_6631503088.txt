1. Boolean Bypass (SQLi) - 15 pts

Mitigation: Implement parameterized queries (prepared statements) using ? placeholders so the database engine pre-compiles the query structure and treats user input strictly as a passive data literal rather than executable SQL grammar.

2. Shell Out (Command injection) - 15 pts
Flag: FLAG{cmdi_91f24b8d}
Payload: 127.0.0.1;cat /flag.txt
Mitigation: Execute system commands without a shell by passing an argument array with shell=False (e.g. subprocess.run(["ping", "-c", "1", host], shell=False)) and enforce strict allow-list regex validation on the host parameter.

4. Not Your Order (IDOR) - 15 pts
Flag: FLAG{idor_2783e815}
Payload: Log in as alice (POST /login with {"user":"alice","pw":"alicepw"}) to get an auth token, then send GET /api/orders/2 with header "Authorization: Bearer <alice_token>" to view bob's order.
Mitigation: Enforce server-side authorization checks on object access: retrieve the logged-in user identity from the verified session/token and verify that order["owner"] == current_user (or the user has an admin role) before returning the record; return 403 Forbidden otherwise.
==========================================
5. Forge Ahead (Broken JWT) - 15 pts
Flag: FLAG{jwt_931ab6c9}
Payload: Construct a forged JWT token with sub="admin" and either set alg="none" (token: eyJhbGciOiJub25lIiwidHlwIjoiSldUIn0.eyJzdWIiOiJhZG1pbiJ9.) or sign with the hardcoded secret "secret", then send GET /api/admin with header "Authorization: Bearer <token>".
Mitigation: Reject "none" algorithm tokens by explicitly specifying allowed signature algorithms in jwt.decode(..., algorithms=["HS256"]), use a cryptographically strong high-entropy secret stored securely in environment variables, and verify signatures for all tokens before trusting claims.
==========================================

Mitigation: Replace fast, unsalted hashing algorithms (like MD5) with modern memory-hard, computationally expensive password hashing functions such as Argon2id (or bcrypt) using unique per-user cryptographically random salts.

7. Penguin (ECB oracle) - 10 pts [screenshot required]
Flag: Block 1: 3bfd04cc0d7ed55358e2cbe19de21383, Block 2: 3bfd04cc0d7ed55358e2cbe19de21383 (Identical repeated 16-byte blocks prove ECB structure leak)
Payload: python3 -c 'from vulnerable_crypto import encrypt_ecb; c = encrypt_ecb(b"A"*32).hex(); print("Block 1:", c[:32]); print("Block 2:", c[32:64]); print("Match:", c[:32] == c[32:64])'
Mitigation: Switch from ECB mode to an Authenticated Encryption with Associated Data (AEAD) cipher mode such as AES-GCM (or ChaCha20-Poly1305) using a unique, cryptographically random 12-byte nonce for each encryption to prevent deterministic pattern leakage and ensure ciphertext integrity.
